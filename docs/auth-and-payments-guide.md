# 인증/결제 붙이기: 가장 쉬운 경로부터

`llm-runner`는 로그인·결제·회원별 사용량 관리를 대신 해주지 않는다. 여기서는 코딩을 몰라도 가장 적은 설정으로 시작할 수 있는 방법을 순서대로 안내한다. 아래로 갈수록 더 정교하지만 설정이 많아진다 — **처음엔 1번부터 시작하는 걸 권장한다.**

## 0. 먼저 정할 것: "로그인이 꼭 필요한 서비스인가?"

- 무료로 아무나 써도 되는 데모/개인 홍보용 챗봇이라면 로그인 없이 [Next.js 예제](../examples/nextjs-starter)의 rate limit + prompt 길이 제한만으로도 당장 오픈 가능하다.
- **회원별로 사용량을 다르게 주거나(무료 3회, 유료 무제한 등), 결제를 받아야 한다면 로그인이 필수다.** 아래로 진행한다.

## 1. 가장 쉬운 결제: 코드 없는 "결제 링크"

Stripe나 토스페이먼츠는 **코드를 한 줄도 안 짜고** 결제 페이지를 만들 수 있는 기능을 제공한다.

- **Stripe Payment Links**: https://dashboard.stripe.com/payment-links → "새 링크 만들기" → 상품명/가격 입력 → 생성된 URL을 그대로 카카오톡, 웹사이트 버튼 등에 붙이면 끝. 결제 성공 시 이메일로 알림이 온다.
- **토스페이먼츠 결제 링크**: https://www.tosspayments.com 가입 후 대시보드에서 동일한 방식 제공.

이 방식의 한계: "결제한 사람만 챗봇을 쓸 수 있게" 자동으로 막지는 못한다(수동으로 결제자 명단을 확인해서 접근 권한을 줘야 한다). 회원 소규모(수십~백 명 단위)일 때 임시로 쓰기 좋다.

## 2. 로그인 자동화: NextAuth 이메일 매직링크

OAuth 앱 등록(Google/카카오 개발자 콘솔 신청) 없이 가장 빨리 붙일 수 있는 방식이다. 사용자가 이메일을 입력하면 로그인 링크를 받는 방식(비밀번호 없음).

Claude Code한테 이렇게 요청하면 된다:

> "Next.js 프로젝트에 NextAuth 이메일 매직링크 로그인을 붙여줘. OAuth 앱 등록 없이 되는 방식으로. 로그인한 사용자만 /api/ai를 호출할 수 있게 막아줘."

핵심 아이디어만 알아두면 이해가 쉽다:

```ts
// app/api/ai/route.ts에 추가되는 흐름 (예시, 실제 코드는 AI 어시스턴트가 작성)
import { auth } from '@/auth'; // NextAuth 세션 확인

export async function POST(req: NextRequest) {
  const session = await auth();
  if (!session?.user) {
    return NextResponse.json({ error: '로그인이 필요합니다.' }, { status: 401 });
  }
  // 이 아래부터는 로그인한 사용자만 도달한다
  // ... 기존 llm-runner 호출 코드
}
```

이메일 발송에는 Resend(https://resend.com, 무료 플랜 있음) 같은 서비스가 필요하다 — NextAuth 설정 시 같이 안내받게 된다.

## 3. 회원별 사용량(쿼터) 관리

"무료 회원은 하루 3번, 유료 회원은 무제한" 같은 규칙이 필요하면, [`lib/rate-limit.ts`](../examples/nextjs-starter/lib/rate-limit.ts)와 같은 방식(Upstash Redis)을 IP 대신 **로그인한 사용자 ID**로 카운트하면 된다.

```ts
// 개념 예시 — 로그인 세션에서 얻은 user.id를 rate-limit의 key로 사용
const plan = session.user.plan; // 'free' | 'paid' 등, DB에 저장해둔 값
const maxRequests = plan === 'paid' ? 9999 : 3;
const limited = await isRateLimited(`user:${session.user.id}`, ONE_DAY_MS, maxRequests);
```

`plan` 값(무료/유료)은 결제 완료 시 DB에 저장해야 하는데, 이 부분은 결제 서비스(Stripe 등)의 "결제 완료 webhook"을 받아서 처리한다. Claude Code한테 이렇게 요청하면 된다:

> "Stripe 결제 완료 webhook을 받아서, 결제한 사용자의 DB 레코드에 있는 plan 값을 'paid'로 바꿔주는 API 라우트를 만들어줘. 방금 만든 NextAuth 로그인이랑 연결해서, 로그인한 사용자 이메일 기준으로 매칭해줘."

## 4. 요약: 단계별로 언제 넘어가면 되나

**중요: 아래 표의 "추천 단계"는 "그 번호만 하면 된다"는 뜻이 아니라 "그 번호까지 순서대로 다 필요하다"는 뜻이다.** 예를 들어 3번(사용자별 쿼터)이 필요하다면 1번(결제)과 2번(로그인)도 먼저 갖춰져 있어야 한다 — 3번의 코드가 로그인 정보(`session.user`)와 결제 여부(`plan`)를 그대로 가져다 쓰기 때문이다. 표는 "내 최종 목표가 몇 번 단계에 해당하는지" 찾는 용도로만 써라.

| 내 최종 목표 | 몇 번까지 다 필요한가 |
|---|---|
| 그냥 데모/홍보용, 무료 공개 | 0번만 (로그인 없이 rate limit만, 지금 예제 그대로) |
| 소규모 유료 서비스, 회원 관리는 수동으로 해도 됨 | 1번까지 (결제 링크만) |
| 회원가입/로그인 화면이 있어야 함 | 1 → 2번까지 |
| 무료/유료 회원 사용량을 다르게 줘야 함 | 1 → 2 → 3번까지 전부 |

한 번에 다 만들 필요는 없다 — **지금 당장 필요한 목표까지만 이 문서를 순서대로 Claude Code에게 넘기면서 하나씩 진행하면 된다.** 예를 들어 지금은 1번(결제 링크)만 열어두고 손님을 받다가, 나중에 회원이 늘면 이 문서를 다시 열어서 2번부터 이어서 진행해도 된다.
